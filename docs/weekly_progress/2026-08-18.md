## Slide 3 — What the model sees

All directions can share temporal appearance features when six perspective faces from one camera position are ordered as video time. However, nothing in that ordering alone states that pixels on different faces belong to the same 3D surface or spherical ray.

Conclusion: trajectory ordering can reduce difficulty but cannot create spherical topology by itself.

## Slide 4 — Depth and loop comparison

The first six-face ArtiFixer3D+ run was compared with depth plus temporal context and fourteen-face distillation. Depth changed the geometry locally, but warped walls, duplicated edges and ghosting remained. Depth conditioning alone did not make the representation converge to one clean surface.

The comparison used nearest camera-center matching because the depth/loop trajectory had been smoothed and resampled by uniform arc length; equal numeric frame IDs did not represent equal poses.

## Slide 5 — Final framework

Pinhole video → frame extraction → COLMAP cameras and sparse geometry → initial 3DGRUT scene → one shared Gaussian scene → world-locked spherical-snake trajectory → ArtiFixer common temporal stream → pseudo-observations → geometry-constrained ArtiFixer3D distillation → synchronized panoramic rendering → final ArtiFixer3D+ → spherical fusion/ERP projection.

The framework explicitly records that spherical consistency comes from temporal continuity, overlap, real-image anchors and shared 3D feedback—not from native spherical topology inside ArtiFixer.
